# Blender в песочнице

**Версия: 5.0.1 — единственная.** Задача закреплена в `tools/sandbox/bootstrap.sh`
по SHA-256 колеса, подмена не проскочит.

```bash
tools/sandbox/bootstrap.sh
LD_LIBRARY_PATH=/tmp/bpystubs /tmp/bpyenv/bin/python your_script.py
```

## Почему именно 5.0.1

- **Последняя под CPython 3.11** — а 3.11 единственный Python в песочнице.
  Более новые сборки требуют 3.13, а его взять неоткуда: `python.org` и
  GitHub Releases заблокированы (проверял `uv` и `pbs-installer` — оба тянут
  интерпретатор с GitHub).
- **Совместима с моделями, которые уже есть.** Три реальные модели (coin,
  rocket, safe, сделаны в Blender 4.02–4.05) проходят без потерь: GLB на
  выходе совпадает с любым другим Blender байт в байт.
- **Новее — значит без потерь.** Старые файлы новая версия открывает чисто;
  модификаторы (`SUBSURF` и прочие) сохраняются.

## Что работает

| операция | результат |
|---|---|
| импорт `bpy` | ✅ |
| сцена, меши, модификаторы | ✅ |
| арматура, кости | ✅ |
| анимация (keyframes) | ✅ |
| открытие готовых `.blend` | ✅ |
| **экспорт GLB** | ✅ |

Проверка на реальных моделях: `coin.glb` 43 376 Б, `rocket.glb` 236 276 Б,
`safe.glb` 501 772 Б — на обеих версиях Blender файлы идентичны.

## Что НЕ работает: рендер

Ни `BLENDER_WORKBENCH`, ни `CYCLES`, ни EEVEE. Все упираются в одно:

```
Couldn't open libEGL.so.1: libEGL.so.1: cannot open shared object file
```

### Почему это нельзя починить изнутри песочницы

Проверено, а не предположено:

- в системе **нет** ни `libEGL`, ни `libGL`, ни `libGLESv2` (`find /` — пусто);
- `apt` не работает: пакета нет в индексе, root недоступен;
- **ни одно колесо на pypi не содержит `libEGL`** — проверил `pyrender`,
  `moderngl`, `pyopengl`, `glcontext`, `panda3d`, `godot4`, `vispy`;
- **SwiftShader из нашего репозитория не помогает**: он даёт Vulkan
  (`libvulkan.so.1` + `libvk_swiftshader.so`), а не EGL. Подстановка как
  `libGLESv2` не сработала — EGL-символов в нём нет (`nm -D | grep egl` → 0);
- `download.blender.org` заблокирован (`SSL_ERROR_SYSCALL`), поэтому нативный
  Blender недоступен физически.

## Решение: рендерить в Godot

Godot 4.7.2 лежит в репозитории (`tools/vendor/godot/`) вместе со SwiftShader —
тем самым, который даёт программный Vulkan. Это и есть рендер без GPU.

Порядок: Blender делает **геометрию и анимацию** → GLB → Godot рисует кадры.
Так же устроен пайплайн одноимённого проекта: модели валидируются скриптами
(`audit_glb.py`), а не глазами по картинке.

## Если понадобится версия новее

Единственный путь — **другой Python**. С 3.13 открываются сборки до 5.3.0, но
получить его в песочнице нельзя (см. выше). Если среда изменится:

```bash
python3.13 -m venv /tmp/bpyenv
/tmp/bpyenv/bin/pip install 'bpy==5.3.0'
```

Тогда же надо будет перегенерировать стабы X11:
`python3.13 tools/sandbox/bpy_stubs.py <site-packages>/bpy /tmp/bpystubs`.
