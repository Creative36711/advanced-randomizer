# Blender в песочнице: что работает, а что нет

Проверено на деле, а не по описанию. Все цифры — из прогонов в этой сессии.

## Что стоит

`bpy` (Blender как Python-модуль) в venv: **5.0.1** по умолчанию, откат на 4.5.3
одной переменной.

```bash
tools/sandbox/bootstrap.sh                      # bpy 5.0.1
BPY_VERSION=4.5.3 tools/sandbox/bootstrap.sh    # откат
LD_LIBRARY_PATH=/tmp/bpystubs /tmp/bpyenv/bin/python your_script.py
```

Стабы X11 (`tools/sandbox/bpy_stubs.py`) собираются один раз и **подходят к обеим
версиям без изменений**: колесо линкуется с `libXrender.so.1`, `libXfixes.so.3` и
другими библиотеками, которых в песочнице нет.

## Что работает

| операция | 5.0.1 | 4.5.3 |
|---|---|---|
| импорт `bpy` | ✅ | ✅ |
| сцена, меши, модификаторы | ✅ | ✅ |
| арматура, кости | ✅ | ✅ |
| анимация (keyframes) | ✅ | ✅ |
| **экспорт GLB** | ✅ | ✅ |

Тестовая сцена (сфера 24×12 + арматура + анимация) даёт **одинаковый файл байт в
байт** на обеих версиях: 39 756 Б. Разницы в качестве результата нет.

## Что НЕ работает: рендер

Ни `BLENDER_WORKBENCH`, ни `CYCLES`, ни EEVEE. Все упираются в одно:

```
Couldn't open libEGL.so.1: libEGL.so.1: cannot open shared object file
```

### Почему это нельзя починить изнутри песочницы

Проверено, а не предположено:

- в системе **нет** ни `libEGL`, ни `libGL`, ни `libGLESv2` (`find /` — пусто);
- `apt` не работает: пакета нет в индексе, root недоступен;
- **ни одно колесо на pypi не содержит `libEGL`** — проверил `pyrender`,
  `moderngl`, `pyopengl`, `glcontext`, `panda3d`, `godot4`, `vispy`;
- **SwiftShader из нашего репозитория не помогает**: он даёт Vulkan
  (`libvulkan.so.1` + `libvk_swiftshader.so`), а не EGL. Подставить его как
  `libGLESv2` пробовал — EGL-символов в нём нет (`nm -D | grep egl` → 0);
- `download.blender.org` заблокирован (`SSL_ERROR_SYSCALL`), поэтому нативный
  Blender 5.3.0, на который перешёл `vault`, недоступен физически. Плюс их сборка
  под Windows x64, а песочница — Linux.

## Решение: рендерить в Godot

Godot 4.7.2 лежит в репозитории (`tools/vendor/godot/`) вместе со SwiftShader —
тем самым, который даёт программный Vulkan. Это и есть рендер без GPU.

Порядок: Blender делает **геометрию и анимацию** → GLB → Godot рисует кадры.
Так же поступает `vault`: их `smoke.py` проверяет GLB и рендер раздельно, а
модели они валидируют через `audit_glb.py` и `validate_glb.mjs`, а не глазами по
картинке.

## История вопроса

`vault` (приватный? нет — публичный, `Creative-textile/vault`) держал **ровно наш**
контур: `tools/modeling/setup_bpy.sh`, `bpy_stubs.py`, `test_bpy.py`. Сверил
побайтово — **хеши совпадают** с нашими `tools/sandbox/*`:

```
bpy_stubs.py   133 строки   fca3bdc81ac73789…   (vault до удаления = наш)
setup_bpy.sh    80 строк    4b394ff8f11f4284…   (vault до удаления = наш)
```

Удалил их коммит `eecb687` (15.11.2026), решение **D-125**: `vault` переехал на
локальный ПК с нативным Blender 5.3.0, и pip-модуль стал не нужен.

**Вывод:** мы взяли контур, который `vault` выбросил, — но по причине, которой у
нас нет (у них был нативный Blender, у нас его быть не может). Для нашей
песочницы pip-`bpy` остаётся единственным вариантом, а рендер — за Godot.
