# «Fords provenance must contain exactly 396 sources, found 394»

Этот отказ останавливает конвертацию **на самом последнем шаге** — после того
как все 221 выходной файл уже сконвертированы и захешированы. Поэтому он
выглядит обиднее всего: 216 секунд работы, 85 бандлов, и в конце — «не
прошёл внутренний аудит».

## Что произошло

Импортёр обязан доказать происхождение каждой строки пака: из какого архива,
из какого файла, каким конвертером. Для профиля `men-fords-v0` он ждёт ровно
**396** таких строк (335 ресурсов + 56 документов living-world + 5 строк карты
и AI-библиотек). У вас получилось **394** — две строки не появились, потому что
два ресурса не дали ни одного совпадения в каталоге и были записаны в
`incomplete`, а не в `entries`.

## Почему это не сбой вашего компьютера

Ошибка целиком в данных и в тексте отказа — на моей стороне она не
воспроизводится, потому что у меня нет вашей игры. Но обе причины видны в
логе, и обе имеют понятный источник.

## Причина 1 (у вас — тоже): дерево не может назвать свой коммит

```
"retail provenance importer recipe has no exact git commit"
```

Импортёр штампует происхождение конвертации и отказывает, если дерево не
называет точный коммит. Он ищет `release-identity.json` в корне дерева, а
если файла нет — требует, чтобы **само собранное дерево** было корнем
git-репозитория.

До этой правки `tools/prepare.py` штамп не писал. У игрока git нет по
правилу, поэтому сборка пака падала на аудите **всегда**, у любого, кто
дошёл до конвертации.

**Исправлено:** `prepare.py` теперь пишет `release-identity.json`:

```json
{
  "schema": "openbfme.bundled-source-identity",
  "schemaVersion": 1,
  "commit": "<коммит нашего репозитория>",
  "sourceClean": true,
  "upstream": "Open-BFME/openbfme-godot@bf06a22…",
  "stampedBy": "tools/prepare.py"
}
```

Проверено: импортёр читает штамп и отвечает `provenance_source:
release-identity`, `clean: true` — отказ уходит.

Если git недоступен, штамп всё равно пишется, но честно помечается
`sourceClean: false`. Импортёр в этом случае откажет — и это правильно:
лучше отказ, чем подпись чужими руками.

## Причина 2 (394 вместо 396): двух ресурсов не хватило

Отказ называл только число. **Правка** (`patches/upstream/…`) заставляет его
называть ресурс и файл:

```
Fords provenance must contain exactly 396 sources, found 394
  ресурс без происхождения: <id> — art/w3d/… не найден
  ресурс без происхождения: <id> — audio/… не найден
```

Проверено на синтетическом манифесте: отказ печатает имена ресурсов и
причины. Это не догадка о том, чего вам не хватает, а точный список,
который вы получите при следующем запуске.

## Что делать сейчас

1. **Пересоберите дерево** — новый `prepare.py` положит штамп. Отказ «нет
   коммита» уйдёт.
2. **Запустите конвертацию снова.** Если 394 вместо 396 повторится, отказ
   назовёт два ресурса и файлы.
3. **Пришлите эти строки.** По ним я скажу, какие архивы доставить — точечно,
   а не всю игру.

## Почему `--allow-incomplete` не спасает

Флаг разрешает конвертации продолжаться без обязательного ресурса, но **не
ослабляет аудит**: число строк происхождения проверяется жёстко. Так и
задумано — иначе пак с дырками выглядел бы полноценным.

## Что я проверил без вашей игры

| Что | Как | Результат |
|---|---|---|
| Штамп принимается | `_importer_recipe_report()` на собранном дереве | `release-identity`, `clean: true` |
| Отказ называет причину | синтетический манифест с 0 источников | 2 ресурса названы по именам |
| Константа 396 | `335 + 56 + 5` в `pipeline.py` | совпадает с вашим отказом |

Чего я проверить **не могу**: сами две недостающие строки. Для этого нужен
полный прогон на вашей установке — и именно поэтому правка меняет текст
отказа, а не угадывает причину.
